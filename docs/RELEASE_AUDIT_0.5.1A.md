# WitherChat 0.5.1A — предрелизный аудит

Дата проверки: 24 августа 2026 года.

## Результат

В текущем дереве не осталось воспроизводимых блокирующих дефектов приложения. Проверка охватила ядро, интерфейс, Twitch, YouTube, DonationAlerts, OBS-оверлей, защищённое хранение данных, логи, сборку и упаковку. Ограничения внешних сервисов и требования к публично подписанному релизу перечислены отдельно ниже.

## Автоматические проверки

- Строгая Release-сборка всего решения: 0 ошибок, 0 предупреждений.
- Core API: 115 из 115 тестов.
- Avalonia headless UI: 85 из 85 тестов.
- Core smoke test: пройден.
- Desktop smoke test: пройден.
- Профильный стресс-набор DonationAlerts, очереди и YouTube: 80 тестов, три повтора, 240 из 240.
- Очередь донатов: пачка из 100 событий сохраняет FIFO, максимальное число одновременно активных донатов равно 1.
- Защита от повторных действий: 200 нажатий «Повторить» дают одну операцию; 200 нажатий «Скрыть» дают одну серверную команду.
- Форматирование решения: чисто.
- `git diff --check`: чисто.
- Известные уязвимости NuGet, включая транзитивные зависимости: не обнаружены.
- UI Automation: безымянных элементов WitherChat не найдено; внутренние служебные кнопки стандартного Avalonia Slider не являются самостоятельными пользовательскими элементами, сам ползунок подписан.

Первые падения DPAPI и `HttpListener` воспроизводились только внутри ограниченной тестовой песочницы Windows. Те же наборы, запущенные с обычными правами текущего пользователя, прошли полностью: 115/115 и 85/85.

## Исправлено во время аудита

### YouTube

- Заменён ошибочный Web OAuth client на подтверждённый Google Desktop OAuth client.
- Loopback redirect и PKCE проверены через официальный экран Google, который принял адрес локального приложения и определил клиент как WitherChat.
- В приложение не добавляется `client_secret`; для Desktop-клиента он не нужен и не может безопасно храниться в EXE.
- Ошибка конфигурации Web-клиента теперь распознаётся и показывается понятным сообщением вместо общего сбоя входа.
- Ограничены повторы 401, исправлены обновление отклонённого токена, обработка квоты, временных ошибок, сохранение live-chat ID и page token.
- Убрана повторяющаяся строка «YouTube не подключён» в настройках аккаунтов.

### DonationAlerts

- Последовательная FIFO-очередь и единый consumer не допускают параллельное проигрывание.
- Дубликаты по donation ID отбрасываются; live-дедупликация ограничена безопасным FIFO-окном в 10 000 ID.
- Состояния запуска, воспроизведения, завершения и пропуска подтверждаются серверными событиями.
- «Скрыть» недоступна до подтверждённого `start` и после `end`/`skip`.
- Повторные клики защищены атомарными gate-механизмами, а не только визуальным отключением кнопки.
- При потере связи replay не запускается автоматически, pending-команды завершаются ошибкой без зависания интерфейса.
- Исправлены reconnect/backoff, heartbeat, объединённые Centrifugo-пакеты, handshake, смена соединения и проверка widget token.
- Убрана повторяющаяся строка статуса в отключённом окне DonationAlerts; ошибки и процесс подключения по-прежнему отображаются.

### Интерфейс и доступность

- Проверены normal/compact, размеры от 360×400 до 1100×760, RU/EN, тёмная/светлая тема и разные DPI.
- Проверены настройки, обучение, модальные панели, `?`, `X`, Escape, возврат фокуса, tooltips, скрытые scrollbar, колесо и средняя кнопка мыши.
- Проверены Twitch/BTTV/7TV/YouTube-значки и fallback при сетевой ошибке изображения.
- Проверены кликабельные ссылки, сокращённые подписи и полные адреса в подсказках.
- Исправлен QA-сценарий релизного EXE: используется изолированный временный профиль, первый запуск не затрагивает пользовательские настройки, compact включается реальной кнопкой, завершение происходит штатно.
- Compact-снимок Release EXE и штатный выход проверены успешно.

### Надёжность и безопасность

- Сессии Twitch, YouTube и DonationAlerts защищены локальным хранилищем Windows; чувствительные данные не записываются в диагностику.
- Повреждённые настройки восстанавливаются из резервной копии или изолируются без перезаписи пользовательского файла значениями по умолчанию.
- Усилены очистка логов, cache/store-файлы, обработка ошибок завершения и reconnect.
- Для OAuth callback и OBS-оверлея добавлены защитные HTTP-заголовки и CSP.
- Проверка готового приложения использует отдельный каталог данных; реальные пользовательские настройки не изменяются.

### Упаковка

- Публикуются Windows x64/ARM64, Linux x64/ARM64 и macOS x64/ARM64.
- Для Windows формируются обычный и single-file варианты.
- Пакеты не содержат PDB, пользовательских настроек, сессий, token/key/cache-файлов.
- Контрольные суммы, безопасные пути архивов, Unix-права, notices и лицензии зависимостей проверяются автоматически.
- Подробности: [RELEASE_PACKAGING_AUDIT_0.5.1A.md](RELEASE_PACKAGING_AUDIT_0.5.1A.md).

## Внешние ограничения перед публичным релизом

Эти пункты нельзя честно закрыть только локальными тестами:

1. Удалить или отозвать старый Google OAuth client secret, ранее попавший в историю Git, и больше не использовать старый Web-клиент.
2. Если опубликованный в переписке ключ DonationAlerts действующий, его необходимо заменить в кабинете DonationAlerts.
3. Выбрать и добавить корневую лицензию самого WitherChat; лицензии сторонних компонентов уже перечислены.
4. Подписать Windows-сборку Authenticode-сертификатом.
5. Подписать и нотарифицировать macOS-сборки через Apple Developer ID и проверить Gatekeeper.
6. Провести нативный smoke-test на реальных Linux, macOS и ARM64-устройствах.
7. Проверить брендовые материалы владельцем проекта; для Retina macOS желательно подготовить исходный значок 1024×1024 или вектор.
8. Спланировать переход с .NET 8 до окончания его поддержки 10 ноября 2026 года.
9. Direct widget control DonationAlerts использует недокументированный серверный протокол. Детерминированные HTTP/WebSocket-тесты пройдены, но реальные `start`/`skip` на аккаунте пользователя во время аудита намеренно не отправлялись, чтобы не изменять внешний эфир.

## Вывод

0.5.1A готова для локального тестирования и закрытого кандидата в релиз. Для публичного подписанного релиза остаются только перечисленные внешние организационные и платформенные шаги.
