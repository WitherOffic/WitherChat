# WitherChat 0.5.1A — аудит упаковки релиза

Дата проверки: 24 августа 2026 года.

Этот документ относится к сборочной цепочке, версиям, составу пакетов,
лицензиям и CI. Проверка живого интерфейса и сетевых интеграций ведётся
отдельно.

## Итог

Локальная кросс-публикация всех шести RID завершена успешно:

- `win-x64`, `win-arm64`;
- `linux-x64`, `linux-arm64`;
- `osx-x64`, `osx-arm64`.

Структура пакетов пригодна для внутреннего release candidate. Публичную
публикацию пока нельзя считать полностью готовой из-за внешних пунктов в конце
документа: ротации ранее раскрытых ключей, выбора лицензии самого WitherChat,
подписи Windows, Developer ID/notarization macOS и живого запуска на нативных
Linux/macOS/ARM64-системах.

## Исправлено во время аудита

1. Самодостаточные пакеты были переведены с .NET Runtime 8.0.29 на security
   update 8.0.30. Версия runtime теперь задаётся явно и проверена во всех шести
   `runtimeconfig.json`.
2. CI переведён на security-patch SDK 9.0.317. `global.json` оставляет 9.0.316
   минимальной проверенной версией и допускает новый patch той же feature-band.
3. Unix-архиватор больше не зависит от внешних `tar`/`gzip`, не создаёт
   повторяющиеся записи и не записывает Windows-разделители `\` в Linux/macOS
   пути.
4. После создания Unix-архив автоматически проверяется на дубликаты, абсолютные
   пути, `..` и права запуска. `WitherChat`, `createdump`, `install.sh` и
   `uninstall.sh` получают `0755`; обычные файлы — `0644`.
5. Повторная публикация одного номера очищает только точный каталог этой версии,
   поэтому устаревшая архитектура или старый архив не попадут в CI-артефакт.
6. Linux получил переносимый установщик для текущего пользователя. `.desktop`
   создаётся уже на целевом компьютере с реальным абсолютным путём, XDG-каталогом
   и корректным экранированием `%`. Установщик отклоняет относительный
   `XDG_DATA_HOME`, install-root в виде символической ссылки и уже существующую
   временную папку; `.desktop` создаётся через безопасный временный файл.
7. Windows single-file вариант дополнительно упаковывается в ZIP. EXE остаётся
   одним бинарником, а обязательные лицензии доставляются рядом с ним.
8. Во все варианты добавлены `VERSION.txt`, `BUILD_STATUS.txt`, общий
   `THIRD-PARTY-NOTICES.md`, точная лицензия .NET Runtime, платформенные .NET
   third-party notices, полные native notices SkiaSharp/HarfBuzzSharp и лицензия
   Inter.
9. Упаковка останавливается, если обнаружены PDB, пользовательские настройки,
   сессии, widget token, ключ защищённого хранилища, кэш модерации, локальные
   моменты эфира либо отсутствуют лицензии.
10. macOS `Info.plist` дополнен категорией приложения, регионом, версией словаря
    и проверенным минимумом macOS 13.0.
11. GitHub Actions получили ограничения времени и закреплены на точных commit
    SHA (`checkout` 4.4.0, `setup-dotnet` 4.3.1, `upload-artifact` 4.6.2), а не
    на изменяемых major-тегах. Restore останавливает сборку на NuGet audit
    warning, а отдельный шаг сохраняет полный отчёт по direct/transitive
    уязвимостям в CI-логе.
12. Windows ZIP и весь macOS `.app` теперь проходят встроенную проверку
    безопасных путей, обязательных notice-файлов, дубликатов, PDB и случайно
    попавших пользовательских данных.
13. На нативном Ubuntu packaging запускает `sh -n`, устанавливает пакет в
    изолированный временный `XDG_DATA_HOME`, проверяет бинарник/ярлык/иконку и
    выполняет удаление. На macOS `Info.plist` проходит `plutil -lint` перед
    ad-hoc подписью.

`experimental` и `history` прошлых циклов, часть из них содержит PDB. Они не
входят в `current/0.5.1A`, не перечислены в `PACKAGE_LINKS.md` и не загружаются
текущим CI. Эти старые каталоги нельзя выдавать как релиз; источником релиза
служит только заново созданный точный каталог версии.

## Зависимости, которые не обновлялись автоматически

- `SkiaSharp` 3.119.4 имеет новую major-ветку 4.x. Major-обновление не принято
  без отдельного визуального и нативного регрессионного прогона; известной
  уязвимости в используемой версии NuGet-аудит не нашёл.
- Новые major-версии xUnit и Test SDK относятся только к тестовой инфраструктуре
  и не входят в приложение. Их обновление не должно смешиваться с релизным
  исправлением.
- NuGet помечает старые `Microsoft.NETCore.Platforms`,
  `System.Diagnostics.DiagnosticSource` и `System.Security.AccessControl` как
  deprecated только в transitive-графе текущего test runner. Они не входят в
  desktop-пакет и известных уязвимостей не имеют; исчезнут при отдельном
  major-обновлении xUnit/Test SDK.
- Transitive-обновления HarfBuzz и Tmds.DBus определяются совместимой версией
  Avalonia/SkiaSharp и не должны форсироваться отдельно.

## Обязательные внешние действия до публичного релиза

1. **Отозвать и перевыпустить прежний Google OAuth client secret.** Он удалён из
   текущего дерева, но присутствует в истории Git начиная с commit `4c16a67`.
   Перезапись истории в рамках этого аудита намеренно не выполнялась. После
   ротации старое значение должно быть навсегда недействительным.
2. **Отозвать переданный вручную DonationAlerts API key**, если он ещё активен.
   В текущем дереве и собранных пакетах его нет, но значение уже было показано в
   рабочей переписке и не должно считаться секретным.
3. **Определить лицензию самого WitherChat.** В корне репозитория нет `LICENSE`;
   `THIRD-PARTY-NOTICES.md` покрывает только сторонние компоненты и прямо не
   лицензирует WitherChat. Владелец проекта должен выбрать условия до публичного
   распространения исходников.
4. **Подписать Windows EXE/ZIP происхождением релиза.** Текущие PE-файлы имеют
   статус `NotSigned`; необходим Authenticode-сертификат и проверка подписи после
   окончательной сборки.
5. **Собрать и проверить macOS на macOS.** CI создаёт только ad-hoc подпись для
   структурной проверки. Публичному пакету нужны Developer ID Application,
   hardened runtime, notarization и проверка Gatekeeper.
6. **Проверить Linux и ARM64 на реальном оборудовании.** На Windows подтверждены
   формат, архитектура и содержимое, но бинарники Linux/macOS и Windows ARM64
   здесь физически не запускались.
7. **Проверить правила использования платформенных логотипов** владельцем
   продукта. Источники и официальные brand guidelines записаны в
   `Assets/Brands/SOURCES.md`, а trademark disclaimer включён в notices.
8. **Запланировать переход с .NET 8 до 10 ноября 2026 года.** После окончания
   поддержки нельзя продолжать выпускать обновления на неподдерживаемом runtime.
9. **Подготовить нативный исходник иконки 1024×1024 для macOS.** Текущий ICO
   качественно покрывает Windows/Linux до 256×256, но не содержит 512/1024px.
   Для Retina-иконки нужен оригинал высокого разрешения или вектор, а не
   программный upscale текущего растра.

Файлы SHA-256 подтверждают целостность только при доставке по доверенному
каналу. Неподписанный `SHA256SUMS.txt` сам по себе не подтверждает издателя.
